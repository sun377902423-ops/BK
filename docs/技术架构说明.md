# BKSYS-MED 远程医疗会诊系统 — 技术架构说明

## 一、系统整体架构

系统采用**前后端分离**的 B/S（浏览器/服务器）架构，所有功能通过浏览器访问，无需安装客户端软件。用户通过电脑或手机上的浏览器即可完成全部操作。

```
┌──────────────────────────────────────────────────────────┐
│                    用户访问层                              │
│       电脑浏览器（Chrome/Edge/Safari）                     │
│       手机/平板（Android 浏览器或 APK）                     │
└──────────────────────┬───────────────────────────────────┘
                       │ HTTPS 加密传输
┌──────────────────────▼───────────────────────────────────┐
│                  接入层（Nginx 反向代理）                    │
│          ┌───────────┬───────────┬──────────┐             │
│          │           │           │          │             │
│    ┌─────▼─────┐ ┌──▼───┐ ┌────▼────┐ ┌───▼────┐        │
│    │ 系统前端   │ │ 影像  │ │ 影像    │ │ 视频    │        │
│    │ 业务界面   │ │ 查看器│ │ 服务器  │ │ 通话    │        │
│    │ (React)   │ │(OHIF) │ │(Orthanc)│ │(LiveKit)│        │
│    └───────────┘ └──────┘ └─────────┘ └────────┘        │
│                    │                                     │
│              ┌─────▼─────┐                                │
│              │  后台 API  │                                │
│              │ (Fastify)  │                                │
│              └──┬─────┬──┘                                │
│           ┌─────▼┐ ┌──▼──────┐                            │
│           │ 业务  │ │ 影像数据 │                            │
│           │ 数据库 │ │ (PACS)  │                            │
│           │(PG)   │ │(Orthanc)│                            │
│           └───────┘ └─────────┘                            │
│                                                           │
│           全部运行在本地机柜中的主服务器上                     │
└──────────────────────────────────────────────────────────┘
```

## 二、部署架构

### 2.1 物理部署

所有服务部署在**本地机柜**中，通过企业宽带接入互联网。

```
                   互联网（企业宽带，固定公网 IP）
                          │
                      路由器/防火墙
                   （端口映射到内网）
                          │
              ┌───────────┴───────────┐
              │                       │
         ┌────▼────┐           ┌──────▼──────┐
         │ 主服务器  │           │    NAS      │
         │ 联想 SR588│           │  绿联/群晖   │
         │ 2U 机架式 │           │  2盘位      │
         │          │           │  8TB RAID 1 │
         └──────────┘           └─────────────┘
              │                       │
              └──────────┬────────────┘
                         │
                   ┌─────▼──────┐
                   │ H3C 交换机  │
                   │ 8口千兆     │
                   └────────────┘
                         │
                   ┌─────▼──────┐
                   │ CT/MR 设备  │
                   │ (DICOM上传) │
                   └────────────┘
```

### 2.2 软件服务清单

| 服务名称 | 功能 | 部署位置 |
|---------|------|---------|
| **Nginx** | 统一入口、HTTPS 加密、请求转发 | 主服务器 |
| **系统前端** | 用户操作界面（React） | 主服务器 |
| **后台 API** | 业务逻辑处理（Fastify） | 主服务器 |
| **业务数据库** | 存储患者/会诊/报告等数据（PostgreSQL） | 主服务器 |
| **影像服务器** | 接收和存储 DICOM 影像（Orthanc） | 主服务器 |
| **影像浏览器** | 在线阅片工具（OHIF Viewer） | 主服务器 |
| **视频通话服务** | 实时音视频通话（LiveKit） | 主服务器 |

> 所有服务运行在同一台主服务器上，通过 Docker 容器管理。

## 三、核心业务流程

### 3.1 影像接收流程

```
CT/MR 设备完成扫描
       │
   自动推送 DICOM 数据（端口 4242）
       │
   Orthanc 影像服务器接收并存储
       │
   系统后台自动同步检查记录
       │
   医生在页面看到新检查 → 点击查看影像
```

### 3.2 远程会诊流程

```
本地医生创建会诊（选择患者 + 关联检查）
       │
   邀请中国远程专家（系统发送通知）
       │
   专家接受邀请
       │
   进入会诊室 → 视频通话 + 同步阅片 + 记录体征
       │
   会诊结束 → 本地医生撰写报告
       │
   报告提交 → 专家签署 → 归档
```

### 3.3 影像归档流程

```
影像到达主服务器（SSD 高速盘）
       │
   医生阅片（从 SSD 读取，速度快）
       │
   会诊和报告完成后
       │
   自动或手动迁移至 NAS 长期归档
       │
   NAS 按日期/患者分类保存
```

## 四、数据存储

| 数据类型 | 存储位置 | 容量估算 | 说明 |
|---------|---------|---------|------|
| **业务数据** | 主服务器 PostgreSQL | 约 10GB/年 | 患者/会诊/报告/消息 |
| **近期影像** | 主服务器 SSD 数据盘（4TB） | 约 1TB/年 | 医生频繁访问的影像 |
| **长期影像** | NAS 机械硬盘（8TB RAID 1） | 约 1TB/年 | 归档影像，5-8年容量 |

## 五、安全体系

| 保护层级 | 措施 |
|----------|------|
| **传输加密** | 所有数据传输使用 HTTPS 加密 |
| **登录验证** | 账号密码 + JWT 令牌（12小时过期） |
| **权限控制** | 4种角色（管理员/本地医生/远程专家/技师），38项细粒度权限 |
| **操作日志** | 关键操作记录到系统日志，可追溯 |
| **数据备份** | 数据库定期备份 |
| **硬件保护** | UPS 断电保护，保障正常关机 |
