# BKSYS-MED 远程医疗会诊系统 — 产品功能说明

## 1. 产品概述

BKSYS-MED 是一套面向"发展中国家基层医院 → 国内三甲专家"场景的跨国远程医疗影像会诊系统。系统以**医学影像查看为核心**，整合**实时视频通话**、**病历报告撰写**、**患者体征数据记录**等功能，实现从影像采集、远程诊断到报告签署的完整工作流程。

| 项目 | 说明 |
|------|------|
| 目标用户 | 布基纳法索等非洲法语区基层医院 与 中国三甲医院专家 |
| 网络环境 | 通过 Starlink 卫星互联网连接，服务器部署在阿里云 |
| 核心价值 | 解决跨国医学影像传输、专家远程实时会诊、多语言协作 |
| 部署方式 | 全部安装在用户自己的服务器上，数据不外传 |
| 移动端 | 支持 Android 手机和平板，随时查看影像和参与会诊 |

## 2. 系统如何工作

### 整体流程示意

```
用户通过电脑或手机的浏览器访问系统
        │
   ┌────┴──────────────┐
   │                   │
 系统前端界面        系统后台服务
（操作页面）       （处理业务逻辑）
   │                   │
   │              ┌────┴────┐
   │           数据库     缓存服务
   │              │
   ├── PACS 影像服务器 ─── 连接 CT/MR 等影像设备
   │
   ├── 影像浏览器（阅片工具）
   │
   └── 视频通话服务
```

### 系统包含的服务组件

| 组件 | 用途 |
|------|------|
| 前端界面 | 用户操作的所有页面，包括菜单、表格、按钮等 |
| 后台服务 | 处理登录、数据查询、保存等业务逻辑 |
| 数据库 | 存储所有业务数据：患者信息、会诊记录、报告等 |
| 影像服务器 | 接收 CT/MR 设备传来的影像数据，提供给医生查看 |
| 影像浏览器 | 在浏览器中查看医学影像，支持缩放、窗口调整等操作 |
| 视频通话服务 | 支持会诊中的实时音视频通话 |
| 反向代理 | 统一入口，确保所有的访问经过加密传输 |

## 3. 功能模块详解

### 3.1 用户登录与权限管理

系统为不同角色分配不同的操作权限，确保信息安全。

**四种角色及权限范围**：

| 角色 | 主要职能 | 可操作的功能 |
|------|----------|-------------|
| 系统管理员 | 全面管理 | 所有功能，包括用户管理、系统配置 |
| 本地医生（布基纳法索） | 患者诊疗 | 患者管理、查看影像、发起会诊、写报告 |
| 远程专家（中国） | 远程诊断 | 查看患者信息、阅片、参与会诊、签署报告 |
| 技师 | 影像操作 | 患者信息录入、影像上传、设备管理 |

### 3.2 患者管理

- **基本信息管理**：录入和编辑患者的姓名、病历号、性别、年龄、联系方式等
- **病例保护**：敏感病例可设置访问密码，只有授权人员才能查看
- **访问权限申请**：医生可申请查看特定患者的完整信息，由管理员审批
- **信息关联**：一个患者的所有检查记录、会诊记录、报告等相关信息集中展示

### 3.3 影像检查管理

- **自动接收影像**：CT/MR 设备做完检查后，影像数据自动传输到系统，无需人工干预
- **影像查看**：点击检查记录，直接打开影像浏览器查看完整的医学图像
- **搜索查找**：按患者姓名、检查编号等关键词快速定位需要的检查记录
- **手动上传**：支持上传 DICOM 格式的影像文件（.dcm 或压缩包），方便离线数据导入
- **影像浏览器功能**：
  - 浏览全部 CT/MR 断层图像，可逐层查看
  - 支持缩放、平移、窗口宽度/位置调整
  - 中/英/法三种界面语言可随时切换
  - 页面顶部显示自定义品牌名称和标识

### 3.4 影像设备管理

- **设备注册**：录入 CT、MR、DR、超声等影像设备的基本信息
- **连接状态测试**：一键测试设备与系统的连接是否正常
- **网络配置管理**：查看和配置设备连接的地址、端口等信息
- **适配卫星网络**：支持局域网内的设备通过路由器映射方式连接，适用于 Starlink 网络环境

### 3.5 远程会诊（核心功能）

会诊从创建到结束有一个清晰的流程管理，每个阶段都有明确的状态标识。

**会诊的完整流程**：

```
创建会诊 → 邀请专家 → 确定时间 → 进行会诊 → 完成会诊
                                                ↘ 取消 / 归档
```

**会诊中可以做哪些事**：

| 功能 | 具体说明 |
|------|----------|
| 创建会诊 | 选择患者、关联相关检查、填写会诊标题和病情描述 |
| 邀请专家 | 从系统用户中选择专家或其他医生加入会诊，可指定不同角色 |
| 接受/拒绝邀请 | 被邀请人会收到通知，可以选择接受或拒绝 |
| 一键开始 | 发起人点击"开始会诊"，所有已接受邀请的人自动进入视频会议室 |
| 视频通话 | 会诊中多方实时视频通话，画面清晰，支持加密传输 |
| 文字聊天 | 会诊过程中可以发送文字消息，方便记录和引用 |
| 同步查看影像 | 会诊界面可以同步打开影像浏览器，双方同时查看同一份影像 |
| 记录体征数据 | 会诊中可填写患者的血压、心率、体温等体征数据，保存后长期可用 |
| 消息提醒 | 收到会诊邀请或状态变化时，页面右上角会有通知提示和声音提醒 |
| 会诊归档 | 会诊结束后可归档保存，方便日后查阅 |

### 3.6 报告管理

诊断报告是远程会诊的最终产出物，系统提供了结构化的报告撰写工具。

- **新建报告**：选择患者，关联相关的会诊和检查记录
- **报告内容**：
  - 检查所见：描述在影像中观察到的具体表现
  - 诊断意见：根据影像表现给出的专业判断
  - 建议：后续治疗或进一步检查的建议
- **体征数据记录**：可在报告中附加记录以下 8 项生命体征数据
  - 血压、心率、体温、呼吸频率
  - 血氧饱和度、血糖、体重、身高
- **心电数据记录**：可在报告中附加记录心电图结果和各项心电参数
  - 心电图结果描述、心率、PR 间期、QRS 时限、QT 间期、诊断解读
- **报告流转**：
  - 草稿 → 提交给专家审阅 → 专家签署确认
- **权限细分**：创建、编辑、查看、提交、签署、删除等操作可分别授权给不同角色

### 3.7 通知与提醒

- **未读消息提示**：页面右上角铃铛图标显示未读通知数量
- **自动刷新**：系统每隔十几秒自动检查是否有新通知
- **点击跳转**：点击通知可直接跳转到对应的会诊详情
- **声音提醒**：收到新通知时有提示音（可在个人设置中开关和调节音量）
- **通知分类**：会诊邀请通知、会诊状态变更通知等

### 3.8 系统管理功能

| 管理模块 | 功能说明 |
|----------|----------|
| 用户管理 | 添加/编辑/删除系统用户，分配角色 |
| 医院管理 | 管理合作医院的信息 |
| 角色权限 | 自定义角色名称和权限范围 |
| 操作日志 | 查看系统的操作记录，便于追溯 |
| 数据备份 | 对数据库进行备份管理，保障数据安全 |
| 界面布局 | 左侧菜单栏可收起/展开，收起后内容区显示更宽 |

### 3.9 多语言支持

- 系统界面支持中文、英语、法语三种语言
- 用户可随时在页面右上角切换语言
- 影像浏览器的界面文字也会跟随切换语言

### 3.10 安全保障

| 保护层级 | 措施 |
|----------|------|
| 传输加密 | 所有数据传输都经过加密，防止信息被截获 |
| 登录验证 | 每次使用需要账号密码登录，令牌定期失效 |
| 权限控制 | 严格按照角色分配权限，不同角色看到的功能不同 |
| 操作记录 | 重要操作会被记录到日志，便于审计 |
| 防误操作 | 关键操作有确认提示，页面异常时有容错保护 |

## 4. 并发容量规划

### 4.1 典型使用场景

| 场景 | 数量 |
|------|------|
| 同时进行的视频会诊 | 5 — 8 场 |
| 同时在线查看影像的用户 | 20 人 |
| 每场会诊的参与人数 | 2 — 5 人 |
| 同时使用系统的总人数 | 约 40 — 60 人 |

### 4.2 各功能对带宽的需求

#### 视频通话

视频通话是占用带宽最多的部分。每一路视频画面都需要一定的传输速度来保证清晰度：

- **8 场会诊同时进行时**，视频通话总体需要的带宽约 70 — 100 Mbps
- 系统为视频通话预留了足够的数据通道，可以支持更多会诊同时进行

#### 查看影像

医生查看 CT/MR 影像时，需要从服务器加载图像数据：

- **20 人同时阅片**：每人浏览不同患者的检查数据
- **加载影像的瞬间**：需要较大的带宽（短时间峰值约 200 Mbps）
- **正常操作时**：平均带宽需求约 30 — 50 Mbps，比较平稳

#### 日常操作

填写报告、查询患者、查看通知等日常操作对带宽的需求很低。

### 4.3 推荐的服务器配置

| 负载等级 | 适用场景 | 建议配置 |
|----------|----------|----------|
| 标准配置 | 5 场会诊 + 10 人阅片 | 4 核 CPU / 16 GB 内存 / 200 Mbps 带宽 |
| 高配 | 8 场会诊 + 20 人阅片 | 8 核 CPU / 32 GB 内存 / 500 Mbps 带宽 |

> **主要瓶颈**：视频通话占用的带宽最大。建议按上述配置选择，以保证会诊画面流畅。

### 4.4 需要开放的网络端口

为了让系统各组件间顺畅通信，需要在服务器的防火墙上开放以下端口：

| 端口 | 用途 | 说明 |
|------|------|------|
| 80 | 网页访问（HTTP） | 可自动跳转到加密访问 |
| 443 | 网页访问（HTTPS） | 加密访问的主端口 |
| 4242 | 接收 CT/MR 影像数据 | 影像设备通过此端口上传图像 |
| 7880-7882 | 视频通话 | 视频会议的核心端口 |
| 50000-50100 | 视频通话媒体数据 | 传输音视频画面 |

### 4.5 数据存储量估算

| 数据类型 | 一年存储量预估 | 说明 |
|----------|---------------|------|
| 患者信息 | 5,000 — 10,000 条 | 按每月约 500 新患者 |
| 检查记录 | 10,000 — 20,000 条 | 每患者平均 2 — 3 次检查 |
| 会诊记录 | 2,000 — 5,000 条 | 每月约 200 场会诊 |
| 会诊消息 | 50,000 — 100,000 条 | 平均每场会诊 20 条消息 |
| 诊断报告 | 2,000 — 5,000 条 | 与会诊数量相当 |
| 医学影像 | 200 GB — 1 TB | 取决于 CT 检查频率和图像分辨率 |

### 4.6 系统运行建议

1. **影像加载优化**：重复查看的影像会自动缓存，再次打开速度更快
2. **通知检查频率**：当前设置对服务器负载很小，无需调整
3. **数据库维护**：系统会自动处理数据索引，日常查询速度快
4. **视频质量**：在网络条件不佳时，系统会自动调整画质以保持通话流畅

## 5. 典型工作流程

### 5.1 跨国会诊完整流程

```
第一步：布基纳法索技师为患者做 CT 扫描
        │
第二步：CT 设备自动将影像数据传输到系统服务器
        │
第三步：本地医生登录系统 → 确认影像已收到 → 创建远程会诊
        │
第四步：系统根据患者信息关联检查记录，邀请中国远程专家
        │
第五步：远程专家收到通知提醒 → 接受邀请 → 进入会诊室
        │
第六步：双方通过视频通话实时交流，同时查看同一份影像
        │
第七步：会诊过程中记录患者的体征数据（血压/心率/体温等）
        │
第八步：会诊结束后，本地医生撰写诊断报告
        │
第九步：报告提交给远程专家审阅 → 专家签署确认 → 报告归档保存
```

### 5.2 日常影像诊断流程

```
患者做 CT 检查 → 影像自动传到系统
    → 医生在影像浏览器中阅片诊断
    → 撰写诊断报告（可附体征数据和心电图数据）
    → 提交报告 → 上级医生审阅签署 → 归档
```
